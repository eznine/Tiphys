# 方法卡（Method Cards）

方法卡回答的是"这类问题该怎么做、什么时候不该这么做"，与工具目录（"有哪些工具"）**分开检索**。工具目录解决"名字对不上就找不到"，方法卡解决"找到了工具也会用错"。

- 数据源：`src/lib/methods.ts`（唯一事实来源，卡片是数据不是散文）
- 测试：`tests/methods.test.ts`（字段完整性、工具 ID 真实存在、契约覆盖、触发词检索）
- 检索入口：`findMethods(query)`，只做触发词包含匹配，不参与工具排序

## 2. 卡片结构

每张卡都有固定七段，缺一段测试就失败：

1. **触发词**：用户真实会打的短语，不是工具名。
2. **前置条件**：数据、CRS、单位上的硬要求。
3. **类型化护栏**：`crs` / `units` / `overlay-double-count` / `nodata` / `predicate` 五类，每类写清检查不变量和无法判断时的下一步。
4. **追问条件**：不澄清就会做错的选择（单位、谓词、分组字段、NoData 处理）。
5. **禁止误用**：最常见、后果最严重的错误做法。
6. **验收规则**：结果"可交付"而不只是"跑完了"的判据。
7. **正反例**：正例给出应选的工具；反例可以是"没有工具该被执行"。

## 3. 与工具目录的边界

- 工具检索（`search.ts`）只看名称、别名、描述、类别，不读方法卡；方法卡检索只看触发词，不读目录。两者在 Agent 提示词里**分别注入**，避免互相污染排序。
- 契约支持矩阵（`OPERATION_SUPPORT`）优先于方法卡：卡片描述 `gis.dissolve` 时，必须按矩阵说明"浏览器端不可用、需桌面引擎"，测试会检查这一点。
- 卡片不承诺未测量的能力：`zonal-stats` 只在桌面 Python 支持矩阵为真后关联执行契约；浏览器 WASM 的同名工具仍是栅格分区，不能承接矢量分区。
- 护栏不是文章库：只随命中的 1–2 张方法卡进入 Agent 提示词，不建向量索引，也不把整篇外部 Skill 塞进上下文。

## 4. 关键护栏

- **CRS**：显示用 WGS84 不等于分析 CRS；叠加、距离和面积必须在明确的投影米制 EPSG 下运算。缺失时追问或拒绝，绝不猜。
- **单位**：距离、坡度、像元尺寸、面积/长度分别标明单位；换算只做一次，裸数字不能默认成度或米。
- **叠加重复计数**：`intersect` 后一个源面会被切成多块。直接 `sum(area)` 会重复计数；必须按唯一源 id 去重、先 `union`/`dissolve`，或让用户明确选择"按切片各计一次"。
- **NoData / 谓词**：分区统计要说明 NoData 是忽略还是当 0；"范围内"要说明边界接触和包含关系。

## 5. 增补规则

- 新卡必须给出至少 3 个触发词、1 条前置条件、至少 1 条类型化护栏（含 `check` 与 `next`）、1 条误用、2 条验收。
- 正例工具 ID 必须同时能在 shell 目录（`catalog.json` 的 `name`）或 WASM 目录（`wasm-catalog.json` 的 `id`）中找到，否则测试失败。
- 若方法有共享契约，填 `operation`；若该操作在两端都不支持，不能填 `operation`，只能在文案里说明为设计稿。
