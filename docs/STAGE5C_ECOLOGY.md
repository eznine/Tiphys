>
> 结论先行：**最小成本廊道子集已闭环**——任务卡 `ecology-corridor` 用同一套源地/目的地几何，在阻力方案 A/B（另加更强阈值 C 作敏感性对照）上执行 `wasm_cost_distance → wasm_cost_distance → wasm_corridor`。`npm run vertical:ecology` 三方案 **结构 3/3、成本单调性通过、同 CRS/网格通过、auditRuns 0 违规**，并导出方案 B 廊道 GeoTIFF + sha256。**阻力权重全部是用户给定的合成方案，不是生态学推断；真实阻力、Circuitscape、InVEST、MSPA、Linkage Mapper 均未测。**

## 2. 参数口径

| 项目 | 取值 | 语义与依据 |
|---|---|---|
| 执行链 | `wasm_cost_distance(source, cost)` ×2 → `wasm_corridor(cost1, cost2, percent)` | 工具名与参数名来自实际 WASM catalog；已用 80×60 合成网格探测可执行 |
| 廊道面定义 | 两个累积成本面逐像元相加 | 廊道表面最小值 = 源地集到目标集的最小总阻力成本；这是本纵向的唯一成本不变量 |
| 近最优带 | `percent = 5`（高于廊道最小值 5%） | 只用于交付视图与“非空”检查，不参与成本单调性判断；`0` 只保留严格最小值像元 |
| 阻力权重 | 用户提供，A/B/C 为合成方案 | **不推断物种扩散、栖息地质量或保护优先级**；产品卡明确写明 |
| 方案 A | 基础阻力约 0.75–1.25 | 正值、全网格可通行 |
| 方案 B | A + 中带 8 列（36–43，宽 240 m）阻力 +8 | 中带仍可穿越，但最小总成本应上升 |
| 方案 C | A + 同一中带阻力 +16 | 只作更强屏障的单调性对照，不是第三个“科学方案” |
| 源地/目的地 | 西侧/东侧各 5×10 正像元 | 两方案 bytes 完全相同；不是真实栖息地斑块 |
| CRS/像元 | EPSG:32650 / 30 m，全部 4800 像元有效 | 独立回读核对 shape、CRS、transform、bounds |

## 3. 实测结果（2026-10-25，Node 20 / geolibre-wasm 1.7.1）

| 方案 | 中带阻力增量 | 结果 | 廊道网格 | 5% 带有效像元 | 廊道最小成本 | 廊道最大成本 |
|---|---:|---|---:|---:|---:|---:|
| A | +0 | completed | 80×60 | 785 | 1631.532 | 1713.090 |
| B | +8 | completed | 80×60 | 1279 | 3551.532 | 3729.076 |
| C | +16 | completed | 80×60 | 1735 | 5471.532 | 5745.015 |

**差异解释**：在中带屏障变强时，最小成本路径的总阻力成本从 A 的 1631.532 升到 B 的 3551.532，再升到 C 的 5471.532。这里比较的是**同一源地/目的地、同一网格上的最小成本数值**，不是真实生态连通性结论。5% 带的有效像元数同时变化，但它不是单调性指标，本纵向不对它作方向性断言。

**程序性验收**（每次运行自动执行）：

1. 任务卡生成的 3 步计划在三个方案上全部 `completed`，无验收失败。
2. 每张廊道栅格 80×60、非空，且最大/最小值为有限正数。
3. 源地与目的地 fixture 的 sha256 跨 A/B/C 完全一致。
4. 三个阻力面共享 CRS/transform/尺寸；所有有效阻力像元严格 > 0。
5. 源地、目的地、廊道与阻力面同栅格；廊道像元不可能落到阻力范围外（独立 rasterio shape/CRS/transform/bounds 复核，非引擎自报）。
6. 廊道最小成本随中带阻力增强不下降（相对容差 `1e-9`）。
7. `auditRuns` 无违规，PlanRun 逐步留痕。
8. 方案 B 输出 GeoTIFF，记录字节数、sha256 与 `.sha256` sidecar。

## 5. NOT_TESTED（明确未测）

- **真实景观阻力/物种权重**：没有真实扩散阻力、土地利用重分类、专家权重或物种参数。
- **真实栖息地斑块与栅格化**：fixtures 直接给出源地/目的地栅格；矢量 `habitat_patches.geojson` 只用于 UI 图层练习，未纳入任务链。
- **`wasm_cost_pathway` 路径几何**：本轮交付的是 `cost1+cost2` 廊道面；其最小值代表最小成本路径成本。路径像元/折线并未导出，也没有声称已验证。
- **Circuitscape / Omniscape 电流连通**：未接入；本卡不是电流模型。
- **InVEST 生境质量、碳储量、MSPA、斑块/网络指标**：均未实现。
- **ArcPy Linkage Mapper**：只借鉴“源地 → 阻力 → 最小成本廊道”的概念，没有复制或移植 ArcPy 代码。
- **真实敏感性/不确定性分析**：只有 3 个合成屏障强度；没有权重扰动分布、置信区间或情景统计。
- **移动端真机执行**：与 5A/5B 一样在 Node 子进程执行任务卡同一计划；浏览器/UI 交互由浏览器测试覆盖，未跑真机长任务。
- **矢量廊道面/固定宽度廊道**：未调用 `wasm_optimal_corridor_connections`，也未做宽度敏感性。

## 6. 对阶段 6 的输入

1. 生态纵向的第一条稳定链应是“用户提供阻力 → 成本距离 → 廊道面 → 可解释差异”，而不是先接复杂生态模型。
2. 下一步若需要真实路径交付，需要让计划执行器能引用多输出步骤中的回链栅格，再接 `wasm_cost_pathway`；当前 `@step` 只取首输出，不能假装已通。
3. 真实数据接入前必须先做阻力分类来源、单位、NoData/屏障语义和 CRS/网格体检；否则“廊道更短/更长”没有可核查含义。
4. 方法卡应持续区分：最小成本路径 ≠ 电流连通 ≠ 生境质量 ≠ 景观网络指标。
