# 领域工具链研究：生态、环境、遥感与测绘

证据状态：本文是方向性研究。Linkage Mapper、Circuitscape、InVEST、pylandstats 等项目的开源属性和总体实现方式来自公开资料与领域常识，但本轮没有逐仓库核对最新版本、许可证与依赖。正式复用前必须按 `06_evidence_and_verification.md` 复核。所有“建议”是产品判断，不是这些项目的能力声明。

## 1. 生态廊道：先弄清 Linkage Mapper 到底做了什么

Linkage Mapper 是公开的生态连通性工具，传统实现是 ArcGIS 工具箱/Python（ArcPy）体系，围绕源地、阻力面、成本距离、最小成本廊道和配套的夹点/障碍分析组织工作流。它不是一个单一算法，而是一套把多个栅格运算组织成可解释流程的工具集；不同版本和配套组件的具体名称、参数与输出可能变化，必须以当前官方版本为准。

对 TIPHYS 最重要的判断是：**可以复用它的分析逻辑和术语，不适合直接把它作为一个 ArcGIS 插件整体搬进浏览器。** 原因不是算法不公开，而是运行宿主、栅格 I/O、投影与工具箱交互都绑定在 ArcGIS/ArcPy 上；即使能调用，也会把 TIPHYS 变成“需要 ArcGIS 才能用的壳”。更合理的路线是用 TIPHYS 已有的栅格能力和 Python 栅格栈重新实现流程，并把每一步的语义、参数和验证写清楚。

一个可交付的生态连通性工作流至少包含以下步骤。

| 步骤 | 输入 | 输出 | 关键校验 |
|---|---|---|---|
| 数据体检与统一坐标 | 土地利用/生境、阻力因子、研究区、可选 DEM | 统一分辨率与 CRS 的分析栅格 | 分辨率、NoData、范围、投影单位、重采样方法 |
| 源地/核心区确定 | 生境质量或土地利用、最小斑块面积、连通规则 | 核心斑块栅格/矢量 | 斑块数量、总面积、最小面积、边缘效应 |
| 阻力面构建 | 道路、居民点、水体、矿区、夜光、坡度等 | 阻力栅格与权重表 | 权重来源、归一化、方向性、极值、敏感性 |
| 成本距离与回溯 | 阻力栅格、源地 | 成本距离、回溯方向 | 源地 ID、最大距离、单位、空洞与越界 |
| 廊道提取 | 成本距离/回溯、阈值 | 廊道栅格或矢量、网络节点与边 | 连通性、路径合理性、阈值敏感性 |
| 优先级与障碍 | 廊道、阻力、可选电流/夹点 | 优先修复段、障碍点、核查点 | 排序依据、可解释性、与源地对应 |
| 交付 | 上述结果 | 图件、统计表、报告、外业任务包 | 数字来自工具、参数与血缘完整 |

现有 WASM 目录已经包含成本距离、成本回溯、廊道、路径距离等栅格工具（具体名称与参数以 `src/lib/browser/wasm-catalog.json` 的当前契约为准），因此第一版可以在浏览器/桌面的 WebView 里跑通中小规模栅格。Python 引擎目前主要是矢量 GeoPandas 工具，没有栅格栈；如果要做大范围、高分辨率廊道和分区统计，需要新增 Python 栅格适配器（rasterio/rioxarray 一类）或把任务放到远程执行。这是生态包对架构的直接要求，不应等到模型做完才发现。

## 2. Circuitscape 与 Omniscape：补充电流连通性，不要混为最小成本廊道

Circuitscape 是基于电路理论的连通性分析工具，当前主流实现是 Julia 生态；Omniscape 把类似思想扩展到连续景观，用于识别哪些区域对整体连通性贡献更大。它们与最小成本路径回答的问题不同：最小成本廊道回答“从哪里走代价最低”，电流方法回答“整体景观中电流如何分布、哪些点最关键”。产品中必须分别命名、分别解释，不能把两者都叫“生态廊道”。

工程上不建议把 Circuitscape 放进浏览器 WASM 或手机端。它适合作为桌面 Python/Julia 适配器或受控远程任务，输入输出以栅格和配置为主，运行时间与内存需要预估。第一版生态包可以先只做最小成本廊道，把电流方法作为 P2 增强；如果用户明确需要夹点/障碍分析，再单独接入并做小规模验证。

## 3. InVEST：做精选模型，不做整套搬入

InVEST 是开源的自然资本评估模型集，基于 Python 与地理空间依赖，包含生境质量、碳储量、产水、泥沙、养分、授粉、海岸脆弱性、城市热岛等多种模型。它的价值在于把生态过程整理成可复现的输入表与输出，但每个模型都对土地利用分类、参数表、分辨率和研究区边界有明确要求，直接“一键运行”很容易产生看似合理但不可解释的结果。

TIPHYS 的建议顺序是：先生境质量，后碳储量，再按真实用户需求扩展产水/泥沙等。生境质量能与廊道的源地和阻力分析共享土地利用、威胁因子和敏感度表，适合作为生态包的第一块拼图；碳储量输入相对简单，适合验证“栅格 + 参数表 + 分区统计 + 报告”的通用模式。每个模型都必须内置输入模板、字段与单位检查、缺失数据提示、参数来源记录和结果解释，不允许 Agent 自行编造生态参数。

不建议第一阶段接入整套 InVEST。模型越多，数据准备、版本兼容和结果解释的成本越高；用户真正需要的是能完成一条可信工作流，而不是看到一个模型清单。正式集成时还要核对具体模型的许可证、依赖版本和输出定义，并以官方文档为准。

## 4. 景观格局与源地辅助：低成本、高协同

景观指数与形态学空间格局分析（MSPA）可以作为源地识别、格局评价和廊道前后对比的辅助模块。Python 生态里有 pylandstats 一类开源景观指数库，能计算斑块、边缘、形状、聚集度等指标；MSPA 的传统实现多见于 GUIDOS 等工具，是否适合直接集成需要核实其源码与许可。若要把 MSPA 做进产品，建议先用可验证的形态学开闭运算实现核心概念，并用已知样例对照，不要直接宣称“与 GUIDOS 完全一致”。

这类分析的计算量通常小于廊道和 InVEST，适合作为 P1 增强：在生态包中提供“源地候选”“格局对比”“廊道建设前后变化”三个小工作流，而不是再增加一个孤立的工具箱页面。

## 5. 遥感与数据基础设施

遥感能力的方向不是再堆几百个指数，而是形成“找数据—检查—处理—验证—核查”的链路。STAC 用于数据发现，COG 适合按窗读取大栅格，PMTiles 适合离线/在线瓦片，GeoParquet 与 DuckDB Spatial 适合大规模矢量分析。Sentinel-2/Landsat 的指数、时序和变化检测可以作为桌面/浏览器任务，但必须处理云掩膜、影像时间、分辨率、重采样和 NoData；大范围时序计算优先桌面或远程，手机只查看结果。

GEE 继续保持“未配置/已配置未验证/演示”的三态，不在真实授权与导出链路验证前宣称已接通。未来的远程执行应通过可信服务端代理，前端不保存服务账号密钥。STAC/COG 的引入可以先做数据检索与小范围预览，再逐步接入处理工具，避免一次性引入庞大的数据平台。

## 6. 测绘与测量数据

与测绘用户最相关的不一定是大型平差软件，而是坐标与数据质量：真正转换而非改标签、CGCS2000/WGS84/地方坐标系的正确选择、投影带与中央经线、GNSS 轨迹导入、GPX/DXF/CSV 与属性关联、重复点与异常高程检查、照片与点位关联。现有 Python 引擎已支持 reproject 与基础几何计算，后续可以增加“测量数据体检”工作流。

不建议当前阶段做完整测量平差、RTK/NTRIP 或高精度 GNSS 承诺。手机浏览器无法可靠访问外接 RTK 接收机，后台连续定位也受系统限制；这些能力若成为硬需求，应评估专用原生壳或与现有外业设备配合，而不是在 Web 端假装支持。

## 7. 建议的领域能力优先级

| 优先级 | 能力 | 形态 | 理由 |
|---|---|---|---|
| P0 | 数据体检与坐标/单位向导 | 通用底座 | 所有领域任务的前提，能显著减少错误结果 |
| P0 | 生态连通性最小工作流 | 领域包 | 与现有栅格工具衔接，能形成分析—报告—外业闭环 |
| P0 | 外业核查任务包 | 跨端工作流 | 让分析进入现场，形成手机端价值 |
| P1 | 生境质量、碳储量 | 精选 InVEST 工作流 | 与廊道共享数据，输入相对可控 |
| P1 | 景观指数、MSPA 辅助 | 分析模块 | 低成本增强源地识别与前后对比 |
| P1 | STAC/COG 检索、指数/时序/变化检测 | 遥感工作流 | 形成数据到核查的链路 |
| P2 | Circuitscape/Omniscape | 桌面/远程适配器 | 电流连通性有专业价值，但不适合首版浏览器 |
| P2 | 产水、泥沙、授粉等更多 InVEST | 逐模型接入 | 数据与解释门槛高，不能批量上线 |
| P2 | 测量数据体检、DXF/GPX 导入 | 测绘工作流 | 与现有坐标系能力协同 |
| 暂缓 | 完整 InVEST、Fragstats 复刻、SWAT/HEC/WRF、OpenDroneMap、LiDAR、完整平差、RTK/NTRIP | — | 依赖重、验证成本高，容易分散主线 |

## 8. 生态廊道工作流的验收标准

第一，用合成景观验证算法：构造一个已知最低成本路径的简单阻力面，检查成本距离、回溯和廊道是否落在预期路径；再构造障碍与多源地场景，检查源地归属与连通关系。第二，用真实样例验证数据语义：检查分辨率、CRS、NoData、边缘和研究区裁剪是否一致，重采样是否改变结论。第三，做阻力权重敏感性：至少两组合理权重，比较廊道稳定性；不稳定的区域应标为“需现场核查”，而不是直接给出确定优先级。第四，记录与 Linkage Mapper 的对照边界：哪些步骤语义相当、哪些参数不同、哪些结果（如电流夹点）尚未覆盖。第五，所有输出必须能追溯到输入、权重来源和工具版本。

只有满足这些条件，才能把“生态廊道”作为可交付能力，而不是一张看起来专业的图。
