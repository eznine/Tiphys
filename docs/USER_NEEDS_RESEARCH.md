## 2. 外部信号

### 2.1 高票问题暴露的是"基础操作"，不是高级分析

GIS StackExchange 票数最高的一批问题集中在：

1. 坐标系与投影（projection vs datum、EPSG:3857 vs 4326、WGS84 与 EPSG:4326 的区别、未知 CRS 的 shapefile 如何识别、投影坐标与经纬度互换）。
2. 格式转换与安装（KML↔Shapefile、Windows 上装 GDAL、File GDB 支持）。
3. 最基础的数据操作（计算面要素面积、合并多个矢量图层、重命名字段、添加底图）。
4. 概念辨析（DEM/DSM/DTM、凹包）。

**含义**：大量用户卡在数据准备和坐标系统，而不是卡在"缺一个高级算法"。TIPHYS 已有的近千个工具对这类用户是过载的；真正缺的是**把基础数据活干对、干快、可解释**。

## 3. 对 TIPHYS 的判断

### 3.1 已经做对的

- Ribbon + 常用工具收敛（本轮）：用户确实要 Ribbon，但不要几百个按钮。
- 点选要素看属性（本轮）：Identify 是 GIS 的"呼吸"操作。
- 主题/密度/设置持久化（本轮加固）：配置不丢是底线。
- 本地引擎 + 明确 CRS 校验：正好命中 StackExchange 最大的问题域。

### 3.2 最该补的（按投入产出排序）

**P0：低成本、立刻提升"像个正常 GIS"的体验**

1. **Identify 结果操作**：复制单值/整行、导出、按该值快速筛选（"只看这个值"）、定位到属性表行。识别弹窗已经就位，这是自然的下一步。
2. **图层右键补齐**：重新加载（从原始路径重读）、另存为/导出、图层元数据查看。删除/显隐已加。
3. **符号化升级**：分级设色（手动 min/max + 自动断点）、图例导出。QGIS 高票需求，我们的符号化目前只有单一符号和唯一值。
4. **属性表基础编辑**：字段重命名、字段类型转换、定义查询（表头筛选生成表达式）。这是"基础工作台"缺口里最常用的部分。
5. **数据体检工作流**：一次检查 CRS 缺失、无效几何、重复要素、字段类型混杂、空值比例，输出可执行修复建议。这是 Agent 最能增值的地方（见 §4）。

**P1：形成差异化**

6. **出图工作台（最小版）**：标题、图例、比例尺、指北针、版面尺寸、PNG/PDF 导出。GIS 用户的高频刚需，也是当前明确缺口。
7. **批处理**：同一工具对多图层/多文件批量执行，统一参数、统一进度、结果汇总。Agent 负责生成任务清单，用户确认后执行。
8. **结果解释报告**：字段统计 + 图表 + 自然语言结论 + 下一步建议，一键生成。纯 LLM 增值点。
9. **大图层性能**：渲染期简化、分级加载、长任务进度与取消（已有 job 机制，需覆盖渲染侧）。
10. **工程文件**：保存/打开 `.tiphys` 工程（图层、样式、AOI、选择集、对话摘要），区别于当前的自动快照。

**P2：等前两档稳定后再做**

11. 数据库/云数据连接（PostGIS、SSH 隧道）。
12. 地理配准、栅格几何校正。
13. 布局出图的完整版（多版面、模板、批量出图）。
14. Notebook / 脚本宿主。

## 4. 和 Agent 绑定：哪些功能只有 LLM 才做得好

这些不是"给现有按钮加个聊天框"，而是把**判断、解释、编排**交给 Agent，把**确定性计算**留在工具里：

1. **数据体检与自愈**：确定性检查（CRS、几何有效性、字段类型、重复）由引擎做；Agent 用自然语言解释"为什么错、会有什么后果、建议怎么修"，并在用户确认后调用修复工具。直接命中 StackExchange 第一大问题域。
2. **自然语言定义查询**：用户说"选出人口大于 100 万且靠海的县"，Agent 生成候选表达式/SQL，解释每个条件，用户确认后执行。比让用户学表达式语法现实得多。
3. **结果解读**：字段统计 + 图表 + "这组结果说明什么、有哪些异常、下一步可以做什么"。这是 GIS 软件普遍不做的，也是 Agent 的天然优势。
4. **批量编排**："把 samples 里所有 shp 都做 500 米缓冲并合并"——Agent 拆成任务队列，逐个执行并汇总失败项。
5. **错误恢复**：工具失败时，Agent 读错误、判断是参数问题还是数据问题，换参数重试或给出修复步骤，而不是把堆栈丢给用户。
6. **配方沉淀**：一次成功的多步操作，可以保存为可复用的"配方/工作流"（我们已有 recipe 雏形），下次一句话调用，参数从当前图层/选择集推断。
7. **出图助手**：Agent 根据图层类型和分析目标建议图例分级、配色、标题与版面，用户只做确认。
8. **上下文记忆**：项目记忆里记住单位偏好、常用 CRS、配色习惯，减少重复设置。

## 5. 明确不做 / 暂缓

- 不追求"完整 ArcGIS 对齐"：LiDAR、复杂符号系统、Notebook、完整布局工作台按 P2 排队。
- 不把 GEE 说成已接通：真实授权链路完成前保持"未配置/未验证/演示"三态。
- 不做原生移动 App：移动形态是网页布局（见 `docs/MOBILE_LAYOUT_20261024.md`）。

## 6. 验收方式

上面每一项都必须有可复核证据才移到"已实现"：

- 交互类（识别、右键、符号化）：浏览器/桌面上可重放的操作步骤 + 截图或自动化断言。
- 计算类（体检、批处理、定义查询）：固定样例数据 + 预期结果 + 自动化测试。
- Agent 类（解释、编排、恢复）：mock 模型下的确定性测试 + 一次真实模型端到端记录。

## 7. 下一步（建议顺序）

1. Identify 结果操作 + 图层右键"重新加载"（延续本轮）。
2. 分级设色 + 属性表字段编辑/定义查询。
3. 数据体检工作流（引擎检查 + Agent 解释）。
4. 最小出图工作台。
5. 批处理与结果解释报告。
