# 工具发现质量（阶段 2 · T-005）

> 问题：用户说“统计每个区的平均高程”时，浏览器 Agent 能不能在 999 个工具里找到正确的那一个？
> 复现：`npm run eval:search`（纯离线、真实目录、无模型）。原始数据：[search-eval.json](baselines/stage2/search-eval.json)。
> 注：目录在 2026-10-25 增至 999（新增原生 `centroid`、`drop_empty_geometries`）；下列 207 条标注的检索分数是加入这两个工具前的实测，未重算。

## 1. 标注集

`tests/search/labeled-queries.json`，**207 条**，分三组：

| 组 | 条数 | 内容 | 用途 |
|---|---|---|---|
| `natural` | 116 | 任务说法（“把点做成500米范围”“按字段合并相邻面”） | 真正衡量的能力 |
| `alias` | 69 | 工具别名说法（“点聚合”“凹包”） | 回归护栏，防止重构悄悄破坏已知好用的说法 |
| `gap` | 22 | 浏览器端确实没有对应工具（“人脸识别”“编辑 CAD 图纸”） | 衡量“不懂装懂” |

标注规则：

- 期望值是**工具 id**，来自真实目录；标注阶段不参照 `TOOL_ALIASES`，写完再用 harness 校验每个 id 存在（`missingLabels` 必须为空，测试会失败）。
- 一个查询允许多个正确答案（“把栅格转成矢量面”= `polygonize` 或 `raster_to_vector_polygons`）。
- 标注者就是实现者本人——这是**已知偏差**，所以 `alias` 与 `natural` 分开报告，且门槛只按首次实测值设下限，不按“应该达到”设。

## 2. 指标

| 指标 | 定义 |
|---|---|
| Top-1 | 排名第一的结果在期望集合内 |
| Top-5 | 前五名任一在期望集合内 |
| MRR | 第一个正确结果的倒数排名均值 |
| gap 误召回 | `gap` 查询里出现“高分候选”（score ≥ 40）的比例；这些查询本应回答“做不到” |

## 3. 结果（首次实测 = 当前基线）

| 组 | Top-1 | Top-5 | MRR |
|---|---|---|---|
| natural（116） | **87.1%** | **100.0%** | 0.932 |
| alias（69） | 100.0% | 100.0% | 1.000 |
| gap（22） | 20/22 查询无高分候选；**2 条仍给出高分候选（9.1%）** | | |

改动前（同一套标注）：natural Top-1 **12.3%**、Top-5 12.3%。原因不是排序不好，而是**查询根本没有命中**：中文没有空格，旧实现把整句当一个 token 并要求“所有 token 都命中”，于是“算坡度”匹配不到任何东西。

## 4. 做了什么

1. **中文二元组**：整句 + 相邻二字片段作为 token；至少一个“强证据”命中才返回结果。拉丁词只按整词匹配（否则 `postgis` 的 `st` 会命中 `distance`，实测会把路径距离排到第一）。
2. **意图词表** `src/lib/browser/intents.ts`：把动宾说法（“填洼”“外接圆”“烧录河网”）映射到工具 id。它与工具目录分离——映射错了是一行修改，不会污染工具元数据；boost 只参与排序，不做过滤。
3. **强证据规则**：只有工具名、中文名、标签、人工同义词能构成“命中”；分类与描述只加分，不能单独把工具送进候选。这一条把 gap 误召回从 58.3% 降到 9.1%（配合意图词表与词表负向规则）。
4. **候选精简**：`search_browser_tools` 现在返回 `name / label / 分类 / 一句话摘要 / 输入类型 / 参数（类型、必填、枚举、默认值）`。同一查询 3 个候选 **1,363 字节 vs 2,479 字节** 完整 schema（-45%），并且**不再包含图层参数**——输入类型已经表达了它。
5. **能力过滤**：`inputKind` 与 `provider` 两个过滤器，`x-layer-kind` 未知的工具**不会**冒充矢量或栅格。测试断言：`坡度` 在 `inputKind=vector` 下不得返回 `wasm_slope`。

## 5. gap 查询剩下的 2 个高分候选

| 查询 | 最高分候选 | 判断 |
|---|---|---|
| 人脸识别 | `identify_narrow_polygons`（45） | 弱误召回（刚过阈值） |
| 点云分类 | `classification_accuracy_assessment`（76） | 误召回：栅格分类精度评估，不是点云 |

其余 20 条 gap 查询已经“诚实为空”。9.1% 仍是真实缺陷；阶段 4 的真实模型基线会检验“模型拿到候选后是否胡说”。

## 6. 顺带发现的目录契约缺陷

- `zonal_statistics` 的上游 manifest 把**分区面**声明成 `raster`（“zone-definition raster”）。按“不凭空升级”原则，能力视图如实显示 `raster`，但这意味着**按矢量分区统计目前没有任何工具能诚实承接**——需要阶段 2 的 `gis.zonal_statistics` 设计或上游修正。
- `contours_from_raster` 与 `contour_list` 都叫“等值线”；`cross_tabulation` 与 `tabulate_intersection` 都像“交叉表”。标注集已接受多答案，但工具命名需要在方法卡里写清区别。
